# freee 勤怠サマリー並べ替え

*[English version](README.md)*

freee 人事労務の**勤怠編集画面**のサマリーを、**見たい順に並べ替えて表示し直す**
Chrome 拡張機能（Manifest V3）です。あわせて「労働日数」「総勤務時間」に
**所定（分母）**を付けて「実績 / 所定」の分数で出します。

対象 URL:
`https://p.secure.freee.co.jp/attendances#/work_records/<year>/<month>/employees/<employeeId>`

## なぜ作ったか

- freee のサマリーは**並び順を選べず**、よく見る項目（不足時間・時間外労働）が右の方に散っている
- 「労働日数 20 日」を見て「所定も 20 日」と誤解しやすい
  （実際の「労働日数」は**勤務した日数**で、所定労働日数は別。検証した月では 22 日でした）
- 「不足時間」が何に対する不足なのかが読み取れない

## 表示されるもの

表示順を組み替えた**コピー行**をサマリーの直前に差し込み、**freee の元のサマリーは
折りたたんで隠します**（消しません。行末のボタンでいつでも開けます）。

```
労働日数       総勤務時間         不足時間  時間外労働  法定休日労働  深夜労働  有休取得数
20 日 / 22 日  166:50 / 176:00   9:10     9:30       0:00         0:00     0.5日
                                                              [ freee の元の表示を開く ]
```

- 並び順と項目は `src/lib/render.js` の `SUMMARY_ROW_ITEMS` が持ちます。ここを書き換えれば
  順序も表示項目も変えられます。
- **労働日数と総勤務時間は「実績 / 所定」を 1 行**で出します（freee 側は折り返して 2 行になります）。
- 不足時間・時間外労働などは **freee の表示値をそのまま並べ替えて出すだけ**です。
  読み取れなかった項目は 0 と表示せずに落とします。
- 1 項目も読み取れなかった場合はコピー行を出さず、元のサマリーも隠しません。
- 実績が所定を超えている項目は色が変わります。
- **時間の表記は H:MM に揃えます**（freee の「175 時間 30 分」→「175:30」）。
  「0.5日」のように時間として読めない値はそのまま出します。

なお、この拡張が出す分母は**所定労働時間ベース**です。freee の「残業モニター」は
36 協定（法定労働時間）ベースの予測なので、基準が異なります。

## インストール（パッケージ化されていない拡張機能の読み込み）

1. このリポジトリを clone またはダウンロードします。
2. Chrome で `chrome://extensions` を開きます。
3. 右上の**デベロッパーモード**をオンにします。
4. **「パッケージ化されていない拡張機能を読み込む」**をクリックし、
   `manifest.json` があるこのフォルダを選びます。
5. freee 人事労務の勤怠編集画面を開き直します。

ビルドは不要です（バンドラも npm 依存もありません）。

## 動作確認手順

1. 勤怠編集画面を開き、サマリー（「不足時間」が表示されている領域）の**直前**に
   並べ替えたコピー行が出て、元のサマリーが隠れていることを確認します。
2. コピー行の「freee の元の表示を開く」を押すと元のサマリーが戻り、もう一度押すと
   また隠れることを確認します（状態は保存され、次に開いたときも維持されます）。
3. 「総勤務時間」の分母（所定）と実績の差が、freee の「不足時間」と一致することを
   確認します。
4. 表示を**カレンダー / リスト / テーブル**で切り替えます。値が追随し、
   **コピー行が増殖しない**ことを確認します。
5. 月を切り替えます（`#` のハッシュが変わります）。値が更新されることを確認します。
6. 従業員を切り替えても同様に更新されることを確認します。
7. 拡張機能のツールバーアイコンをクリックして設定を開き、1 日の所定労働時間を変更して保存すると、
   開いている勤怠画面に自動で反映されることを確認します
   （反映されるのは勤務予定から所定を算出できない場合のみ。下記「計算方法」参照）。

## 設定

ツールバーアイコン、または `chrome://extensions` の「拡張機能のオプション」から開きます。

| 設定 | 既定値 | 使われる場面 | 変更する場所 |
| --- | --- | --- | --- |
| 1 日の所定労働時間 | `8:00` | 「勤務予定」から 1 日の所定を算出できないとき（カレンダー / リスト表示、勤務予定が空の行） | 設定ページ |
| freee の元サマリーを折りたたむ | 折りたたむ | 並べ替えたコピー行を出せたときだけ適用されます | 勤怠画面のコピー行にあるボタン |

設定値は `chrome.storage.local` にのみ保存され、Google アカウントには同期されません。

## 計算方法

テーブル表示の列見出し（「勤務日種別」「勤務予定」「休憩」「総勤務」）から列位置を解決し、
行単位で集計します。

1. **所定労働日数** = 「勤務日種別」が `所定労働日` の行数
   （`所定休日` / `法定休日` は除外）。
2. **1 日の所定労働時間** = 「勤務予定」の終了 − 開始 − 「休憩」
   （例：`09:00-18:00` − `1:00` = `8:00`）。
   - **勤務予定が行ごとに違う場合は、勤務予定ごとにグループ化して「日数 × その日の所定」を
     合算**します。時短勤務や期間途中の所定変更があっても「日数 × 一定時間」になりません。
   - 「休憩」が未入力の行は、同じ勤務予定を持つ行の休憩の最頻値で補います。
   - 勤務予定そのものが取れない場合は設定のフォールバック値（既定 `8:00`）を使います。
3. **所定労働時間** = 上記グループごとの合計（「総勤務時間」の分母）。
4. **総勤務時間** = 全行の「総勤務」の合計（休日出勤も含みます）。
5. **労働日数** = 「総勤務」が 0 より大きい行数（未入力の日は数えません）。
6. 実績が所定を超えている場合は、その項目の色が変わります。

### 半休・時短などの扱い

- **半休（有休（半休））**：実働 + 有休分が所定内に計上されて「総勤務」に乗るため、
  `所定 − 総勤務` の単純比較で足ります（freee の「不足時間」と同じ挙動）。特別な処理はしていません。
- **時短勤務・期間途中の所定変更**：勤務予定ごとにグループ化して合算するため対応できます。
- **欠勤・特別休暇・月中入退社**：勤務日種別が `所定労働日 / 所定休日 / 法定休日` 以外の行は
  集計に含めません。月中入退社では在籍前後の日も所定労働日として数えられてしまう可能性が
  あるため、分母が freee の「不足時間」と合わない月があります（下記「制限事項」参照）。

### テーブル表示以外（カレンダー / リスト）

これらの表示には行ごとの「総勤務」「休憩」が揃っていないため、次のように概算します。

- 日数 … `所定労働日 / 所定休日 / 法定休日` ラベルの出現数（**完全一致**でカウントするので、
  凡例や説明文は数えません）
- 総勤務・労働日数 … サマリーの表示値（コピー行に出すために読んだものを使い回します）
- 1 日の所定 … 休憩を各日に紐付けられないため、設定のフォールバック値

日数の合計が 1 か月分（28〜31 日）として不自然な場合や、サマリーの総勤務時間が読めない場合は、
**誤った数字を出さずに**分母を省き、freee の表示値だけを並べ替えて出します。

## コードの構成（バンドラなし）

ビルドステップがないため、モジュール共有には参考実装と同じ dual-mode パターンを使っています。
各ファイルはトップレベルに素の関数を宣言し、末尾に次のガードを持ちます。

```js
if (typeof module !== 'undefined' && module.exports) {
  module.exports = { /* … */ };
}
```

- **content script**：`manifest.json` の `content_scripts.js` に `src/content.js` より**前**に
  並べているので、関数は同じ isolated world のグローバルとして見えます
  （`module` が undefined なのでガードは実行されません）。
- **設定ページ**：`options.html` が `<script src="lib/…">` で読み込みます。
- **Node（テスト）**：`require()` するとガードが働きます。

`chrome.*` と DOM 書き換えに依存するコードは、純粋関数の薄いラッパに閉じています。

### ファイル

```
manifest.json            MV3 マニフェスト（権限・マッチパターン・スクリプト）
src/content.js           勤怠画面で動く唯一の DOM 書き換え層（監視・冪等な挿入・折りたたみ）
src/options.html         設定 UI（ツールバーのポップアップ兼オプションページ）
src/options.js           設定の読み書き
src/styles.css           .fsh-* に閉じたコピー行のスタイル + 設定ページのスタイル
src/lib/time.js          純粋：時間文字列のパースと整形（"166:50" ⇄ 分）
src/lib/config.js        純粋：設定の既定値と正規化
src/lib/aggregate.js     純粋：所定労働日数・所定労働時間・残りの集計
src/lib/extract.js       DOM アダプタ（document を引数で受け取る）
src/lib/render.js        純粋：集計結果 → コピー行の表示モデル（並び順もここ）
test/*.test.js           単体テスト（node:test）
test-helpers/mini-dom.js 依存ゼロの極小 HTML パーサ（jsdom の代替）
test-helpers/fixtures/   勤怠画面を模した HTML フィクスチャ（合成データのみ）
dev/preview.html         実サイトなしで見た目と挙動を確認するローカルプレビュー
icons/                   アイコン（SVG 原図 + 生成した PNG）
scripts/make-icons.sh    SVG から PNG を再生成
scripts/make-preview.js  dev/preview.html を再生成
```

## テストの実行

依存のインストールは不要です。

```bash
node --test
```

フィクスチャは実サイトにアクセスせず開発できるようにするためのもので、すべて合成データです。

| フィクスチャ | 検証内容 |
| --- | --- |
| `table-standard.html` | 実地検証済みのケース：所定労働日 **22 日 / 176:00 / 総勤務 166:50 / 残り 9:10**（半休 1 日・未入力 2 日・休日 9 日・合計行を含む） |
| `table-holidays-only.html` | 休日だけの期間（所定 0 日） |
| `table-over-scheduled.html` | 全日入力済みで超過（160:00 に対して 165:30 → 5:30 超過） |
| `table-mixed-schedule.html` | 勤務予定が混在（通常 15 日 + 時短 7 日 → 162:00） |
| `calendar-view.html` | テーブルが無い表示での概算 |
| `summary-full.html` | サマリー項目が一通り揃ったケース（コピー行の並び替え・凡例の色記号やヘルプアイコン込み） |

`test-helpers/mini-dom.js` は**クラスセレクタを解釈しません**。つまりフィクスチャに
クラス名が付いていてもテストが通るということは、`extract.js` が freee のクラス名に
依存していない証拠になります。

## 実サイトなしで見た目を確認する（ローカルプレビュー）

freee にログインせずにコピー行の見た目と再描画時の挙動を確認できます。

```bash
open dev/preview.html    # macOS。Windows / Linux はブラウザで直接開く
```

`dev/preview.html` はフィクスチャを埋め込んだ 1 枚の HTML で、`src/` の各スクリプトを
`manifest.json` と同じ順序で読み込み、`chrome.storage` だけをスタブしています
（拡張機能のインストールは不要）。

- 画面のプルダウンで 6 種類のフィクスチャ（標準 / 超過 / 勤務予定混在 / 休日のみ /
  カレンダー表示 / サマリー項目が一通り揃った画面）を切り替えられます
- **「再描画」ボタン**で SPA の再描画を再現します。右上の「コピー行: 1 行」が
  維持されていれば多重挿入していません
- コピー行の**トグルボタン**も動きます（`chrome.storage` はメモリ上のスタブなので、
  ページを再読み込みすると既定の「折りたたむ」に戻ります）
- **「月を切り替える」ボタン**で `hashchange` を発生させます

フィクスチャを更新したら `node scripts/make-preview.js` で再生成してください。

## freee の DOM 変更で壊れた場合の修正ポイント

この拡張が freee 側に依存しているのは**表示テキストだけ**です。壊れたら次を順に確認してください。

1. **列見出しのキーワード** — `src/lib/extract.js` の `COLUMN_KEYWORDS`
   （`勤務日種別` / `勤務予定` / `休憩` / `総勤務` の 4 列だけを見ます）。
   列名が変わったらここに追記します。部分一致なので「総勤務時間」でも「総勤務」で拾えます。
   列の**順序**が変わっても修正は不要です。
2. **勤務日種別の判定文字列** — `src/lib/aggregate.js` の `DAY_TYPE_LABELS`
   （`所定労働日` / `所定休日` / `法定休日`）。文言が変わったらここだけ直せば集計は復旧します。
3. **サマリーのラベル** — `src/lib/extract.js` の `SUMMARY_LABELS`
   （`労働日数` / `総勤務時間` / `不足時間`）。`不足時間` は**挿入位置と折りたたみ対象を
   決めるアンカー**（`SUMMARY_ANCHOR_LABEL`）でもあるので、変わるとコピー行が出なくなります。
4. **コピー行の項目と並び順** — `src/lib/render.js` の `SUMMARY_ROW_ITEMS`。
   ラベルは**部分一致**で探すので、freee 側が「時間外労働時間」でも `時間外労働` で拾えます。
   短い方（freee の表示に必ず含まれる方）を書いてください。読み取れない項目は表示から
   落ちるだけで、他の項目には影響しません。

なお、この拡張が差し込んだ要素には `data-fsh` 属性が付いていて、`extract.js` は
その配下をテキストとしても要素としても読みません。**自分が出した「労働日数」「不足時間」を
freee の表示として読み直す事故**を防ぐためなので、DOM を差し込むコードを足すときは
必ず `content.js` の `fshCreateElement()` を使ってください。

いずれの場合も、まず `test-helpers/fixtures/` に新しい DOM を模したフィクスチャを追加し、
テストが落ちることを確認してから直すのが安全です。クラス名や DOM 階層に依存したセレクタは
追加しないでください（壊れやすさの原因になります）。

デバッグのヒント：コピー行が出ない場合は DevTools のコンソールで
`[freee 所定労働時間]` で始まる警告を確認してください。

## 権限を最小化しています

| 権限 | 用途 |
| --- | --- |
| `permissions: ["storage"]` | 1 日の所定労働時間のフォールバック値と、折りたたみ状態の保存のみ |
| `content_scripts.matches` 以外のホスト権限 | **宣言していません**（fetch も chrome.scripting も使わないため、content script の注入に host_permissions は不要） |
| `content_scripts.matches: [".../attendances*"]` | 勤怠画面だけにスクリプトを注入 |

- **外部通信は一切ありません**（`fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` を
  使っていません）。アナリティクスもありません。計算はすべてブラウザ内で完結します。
- **勤怠データは保存しません**。コピー行の描画のためにメモリ上で使うだけです。
- バックグラウンド service worker はありません（外部通信をしないので不要）。
- `chrome.storage.sync` は使いません（Google アカウントに同期させないため）。

詳細は [.github/SECURITY.md](.github/SECURITY.md) を参照してください。

## 制限事項

- 対象は勤怠編集画面（ハッシュに `work_records` を含む URL）のみです。
- コピー行と折りたたみは**画面上の見た目を変えるだけ**で、freee のデータには一切影響しません。
  折りたたみは元の要素を `display: none` にしているだけなので、freee 側が画面を作り直しても
  自動で追随します。
- カレンダー / リスト表示は概算です（上記「テーブル表示以外」参照）。正確な値が必要なときは
  テーブル表示に切り替えてください。
- 月中入退社や期間途中の所定変更がある月は、この拡張が出す所定（分母）が freee の
  「不足時間」と整合しない場合があります。**不足時間そのものは freee の表示値をそのまま
  出している**ので、迷ったらそちらを見てください。
- freee 株式会社とは無関係の非公式なツールです。
