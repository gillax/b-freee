# freee 勤怠サマリー並べ替え 設計書

- 日付: 2026-07-31
- ステータス: 実装済み（動作確認済み）

## 1. 概要 / 目的

freee 人事労務の勤怠編集画面（`https://p.secure.freee.co.jp/attendances#/work_records/...`）のサマリーを、**見たい順に並べ替えて表示し直す** Chrome 拡張。あわせて「労働日数」「総勤務時間」に**所定（分母）**を付け、「実績 / 所定」の分数で読めるようにする。

解決したい課題は 3 つ。

- freee のサマリーは**並び順を選べず**、よく見る項目（不足時間・時間外労働）が右の方に散っている
- サマリーには「労働日数（＝勤務した日数）」しか出ず、**所定労働日数が出ない**。検証した月では労働日数 20 日に対して所定は 22 日で、前者を所定と誤読しやすい
- 「不足時間」が**何に対する**不足なのか画面から読み取れない

## 2. ゴール / 非ゴール

### ゴール

- サマリーの表示順を任意に変えられる（定義は 1 箇所に集約する）
- 「労働日数」「総勤務時間」を **1 行の「実績 / 所定」** で表示する（freee 側は 2 行に折り返される）
- freee の元のサマリーは**消さずに折りたたむ**。いつでも開ける
- freee のクラス名・DOM 階層に依存しない（表示テキストのみに依存する）
- 誤った数字を出すくらいなら**出さない**
- ビルド工程なし・依存ゼロで、コードを読めば全部わかる状態を保つ

### 非ゴール

- freee の元サマリーを CSS `order` で直接並べ替えること（→ 3 節）
- 所定ベースの残り時間・警告・内訳を出すカード（→ 3 節で廃止）
- 英語 UI 対応（別 issue。実装は小さいが freee の英語ラベルの実物が必要）
- Chrome Web Store 公開（当面は load unpacked）

## 3. 採用アプローチ

**コピー行を差し込み、freee の元サマリーを折りたたむ。**

検討した対案は「freee の元サマリーを直接並べ替える」。CSS の `order` を使えば DOM を動かさずに済むが、次の理由で採らなかった。

- 各項目に目印（class / 属性）を付ける必要があり、それは React の再描画で消える
- 表示したい 7 項目以外（所定内労働・欠勤日数・有休残数・遅刻早退時間）を隠すことになり、**freee 本来の情報を消す**
- 「20 日 / 22 日」を 1 行にするには freee 側の項目内部のレイアウトを上書きする必要があり、クラス名依存になりやすい

コピー行方式なら、並び順もレイアウトも自前 DOM の中だけで完結し、freee 側への介入は「兄弟要素を 1 つ挿入」「1 要素の `display` を書き換え」の 2 点に限定できる。

### カードの廃止

初期実装では、サマリーの直後に「所定労働時間と残り」カード（対象期間・所定まで残り・勤務予定の内訳・各種警告・基準の注記）を出していた。コピー行が同じ数字をより見やすく出すようになったため**重複**となり、廃止した。副作用として次の表示は無くなっている。

- 対象期間（表示月と勤務期間のずれの注意喚起）
- 未入力日数・フォールバック値使用・休日出勤・freee の不足時間との差異などの警告
- 「所定労働時間ベースであり、freee の残業モニター（36協定ベース）とは基準が違う」注記（README には残した）

## 4. アーキテクチャ（ファイル構成と責務）

| ファイル | 責務 |
|---|---|
| `manifest.json` | MV3 マニフェスト。権限は `storage` のみ。`host_permissions` は**宣言しない**（宣言済み content script は `matches` だけで注入され、外部通信もしないため不要） |
| `src/content.js` | DOM を書き換える唯一の層。コピー行の描画、折りたたみ、`MutationObserver` による追随、設定の読み書き |
| `src/lib/extract.js` | DOM アダプタ。`document` は必ず引数で受け取る（テストでフェイク document を渡せる） |
| `src/lib/aggregate.js` | 純粋関数。所定労働日数・所定労働時間・労働日数・総勤務時間の 4 つを返す |
| `src/lib/render.js` | 純粋関数。コピー行の表示モデルを作る。**表示順の定義（`SUMMARY_ROW_ITEMS`）はここだけ** |
| `src/lib/time.js` | 純粋関数。時間文字列のパースと整形 |
| `src/lib/config.js` | 純粋関数。設定の既定値と正規化 |
| `src/options.html` / `src/options.js` | 設定 UI（1 日の所定労働時間のフォールバック値） |

## 5. データフロー

```
findSummaryContainer(document)          ← サマリー領域を 1 回だけ特定
  → readSummaryItems(summary, labels)   ← 画面から値を読む唯一の窓口
  → extractAttendance(document, items)  ← テーブル行 or カレンダーからの概算
  → aggregateAttendance(rows, options)  ← 所定・実績の集計
  → buildSummaryRowModel(...)           ← 並び順と表示文字列
  → content.js が DOM を組み立てる      ← textContent のみ（innerHTML 不使用）
```

サマリーの値を読む経路は `readSummaryItems` の 1 系統だけにしてある。コピー行に並べる値も、カレンダー表示の概算に使う「総勤務時間」「労働日数」も同じ戻り値から取るため、走査は 1 回で済む。

## 6. 自分の表示を読み返さないための仕組み

コピー行は元サマリーの**前**に置くため、テキストの出現順でも先に来る。素朴に実装すると、拡張が出した「労働日数」「不足時間」を freee の表示として読み直してしまう。

対策として、拡張が作る要素にはすべて `data-fsh` 属性を付け（`fshCreateElement()`）、`extract.js` はその配下を**テキストとしても要素としても読まない**（`pageText` / `pageElements`）。

## 7. SPA 再描画への追随

月切替・従業員切替・表示切替（テーブル / カレンダー / リスト）はいずれも SPA 内の再描画なので、`hashchange` だけでは足りず `MutationObserver` が必要。

- 自分の DOM 操作中は observer を止める（`fshWithObserverPaused`）
- 自分が差し込んだ DOM 内の変更だけなら再計算しない（無限ループ防止）
- 150ms のデバウンスで再描画の収束を待つ
- 表示モデルを JSON 文字列にして前回と比較し、同じなら DOM を作り直さない
- 折りたたみは**インラインの `display: none !important`**。freee 側のクラスに勝たせるためと、戻すときにインラインスタイルを消すだけで済むため。React が要素を作り直した場合は、前に隠した要素を先に戻してから新しい要素を隠す

## 8. 計算方法

1. **所定労働日数** = 勤務日種別が `所定労働日` の行数（`所定休日` / `法定休日` は除外）
2. **1 日の所定** = 勤務予定の終了 − 開始 − 休憩（例 `09:00-18:00` − `1:00` = `8:00`）
   - 勤務予定ごとにグループ化し、グループごとに「日数 × その日の所定」を合算する。時短勤務や期間途中の所定変更でも「日数 × 一定時間」にならない
   - 休憩が未入力の行は、同じ勤務予定を持つ行の休憩の最頻値で補う
   - 勤務予定が取れない場合は設定のフォールバック値（既定 `8:00`）
3. **所定労働時間** = グループごとの合計（分母）
4. **総勤務時間** = 全行の「総勤務」の合計（休日出勤も含む）
5. **労働日数** = 「総勤務」が 0 より大きい行数

半休は、実働 + 有休分が freee 側で所定内に計上されて「総勤務」に乗るため特別扱い不要。`所定 − 総勤務` が freee の「不足時間」と一致する。

### テーブル表示以外（カレンダー / リスト）

行ごとの「総勤務」「休憩」が無いため概算する。日数は `所定労働日 / 所定休日 / 法定休日` ラベルの**完全一致**での出現数、総勤務と労働日数はサマリーの表示値。日数合計が 1 か月分（28〜31 日）として不自然な場合や総勤務時間が読めない場合は、分母を出さない。

## 9. 安全側に倒している判断

- 読み取れなかったサマリー項目は `0` ではなく**表示から落とす**
- 1 項目も読めなければコピー行を出さず、**元サマリーも隠さない**（読めていないのに隠すと情報が消えるだけになる）
- 勤務日種別が既知の 3 種以外の行（合計行・未知の種別）は集計に混ぜない
- 例外は握りつぶさず `console.warn` に出すが、**画面は壊さない**

## 10. セキュリティ・権限

- 外部通信ゼロ（`fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` を使わない）。これは全ソースを grep する単体テストで機械的に検証している
- `permissions` は `storage` のみ。保存するのは設定 2 つだけで、**勤怠データは保存しない**
- `chrome.storage.sync` は使わない（Google アカウントに同期させない）
- `innerHTML` を使わない。表示はすべて `textContent`
- `web_accessible_resources` を宣言しないので、どの Web ページからも拡張のファイルを読めない
- 依存パッケージゼロ、service worker なし

## 11. テスト方針

- 純粋関数（`time` / `config` / `aggregate` / `render`）は Node 組み込みの `node:test` で直接テストする
- DOM アダプタ（`extract`）は `test-helpers/mini-dom.js`（依存ゼロの極小 HTML パーサ）にフィクスチャを食わせてテストする。**このパーサはクラスセレクタを解釈しない**ので、テストが通ること自体が「クラス名に依存していない」証明になる
- dual-mode（Node では `require`、content script ではグローバル）の**グローバル側の経路**も、manifest の順序でファイルを連結して評価するテストで検証する
- 実サイトなしで見た目と再描画時の挙動を確認できるよう、フィクスチャを埋め込んだ `dev/preview.html` を生成する

## 12. オープン事項 / 将来

- **英語 UI 対応**（別 issue）。方針は「言語判定を持たず日英エイリアスで同時照合」「コピー行のラベルは freee の表示文字列をそのまま流用」。`_locales` によるフル i18n はしない
- ラベル文字列が `extract.js` の `SUMMARY_LABELS` と `render.js` の `SUMMARY_ROW_ITEMS` の 2 箇所にある。片方だけ変えるとカレンダー表示の概算が止まる（テストは落ちるが、原因に結び付きにくい）。1 行のガードアサーションを入れる余地がある
- `extractAttendance` の `viewMode` は現在テストからしか参照していない
- 実地検証は 1 テナント・1 か月分のみ。フレックスタイム制・裁量労働制・変形労働時間制では所定の算出前提が崩れる
